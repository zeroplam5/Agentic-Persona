# 연구 프로젝트 요약: Big Five 페르소나와 기획 아이디어의 품질

최종 갱신: 2026-11-17

## 목적

동일한 LLM 기반 시스템에 Big Five 성격 특성 지시를 부여했을 때 마케팅 캠페인 아이디어의 새로움과 유용성, 결과물의 다양성이 어떻게 달라지는지 실험한다. 관심은 도구 선택 및 재시도 행동이 아니라 **최종 아이디어의 품질**이다. 장기적으로 연구자 본인에게 새로운 관점을 제공하고 발전시킬 가치가 있는지 살핀다.

## 연구 질문

> 같은 모델과 동일한 공통 작업 지시에서 Big Five의 각 특성을 높거나 낮게 지정하면 Wild Ideas 캠페인 아이디어의 새로움, 유용성 및 다양성이 달라지는가?

부수적으로, 성격을 지정하지 않은 기준 조건 및 성격과 무관한 대조 조건과 비교한다. 다른 특성을 고정했다고 해석하기 전에 실제 성격 표현과 교차 영향을 점검한다.

## 과제와 벤치마크

- [Creativity Benchmark](https://arxiv.org/abs/2509.09702)의 **Wild Ideas**를 과제와 최종 결과물 평가 방식의 출발점으로 삼는다.
- 브랜드별로 낯설고 화제를 일으키되 브랜드에 적합한 캠페인 아이디어를 50단어 미만의 한 문장으로 제안하도록 요청한다. 원 프롬프트(Appendix A.1)와 브랜드 표(Appendix A.2)의 확인 기록은 `experiments/pilot_v1/SOURCE_VERIFICATION.md`에 있다.
- 원 벤치마크는 모델 산출물의 인간 선호를 평가한다. 에이전트의 계획·도구 사용·수정·협업 과정 전체를 평가하는 도구가 아니다. 이번 실험은 단일 LLM 호출의 **최종 산출물**만 다룬다.
- 원 벤치마크 그대로의 재현과, 페르소나나 별도 평가 기준을 추가한 **변형 실험**을 구분한다. 원래 시스템 프롬프트에도 대담함·창의성 지시가 들어 있으므로 모든 조건에 동일하게 적용하고 성격 지시와의 상호작용을 고려한다.

## 독립 변수: Big Five

Big Five는 다섯 특성 차원이지 다섯 가지 단일 성격 유형이 아니다: 개방성(O), 성실성(C), 외향성(E), 친화성(A), 신경성(N).

- v1: **특성별 높음·낮음 10조건 + 성격 미지정 기준(BASE) 1조건**, 총 11조건. 나머지 특성은 언급하지 않았다.
- **[결정 2026-11-12] v2:** 나머지 4개 특성은 **Average로 명시**한다. 대조 조건 두 개를 추가한다.
  - CTRL: 성격과 무관한 위약 프로필 문장
  - ALL_AVG: 다섯 특성 모두 Average
  - BASE(성격 미지정)는 유지한다. '보통 지정'은 '성격 미지정'과 같지 않기 때문이다.
- 프롬프트 형식 출처: [Evaluating LLM Alignment under Big Five Personality Prompting](https://ceur-ws.org/Vol-4178/paper6.pdf). 특성 중간값 지정과 교차 효과는 [Does Personality Persuade?](https://arxiv.org/abs/2611.06572)를 참고한다. 번역·수정은 수정 사항으로 기록한다.
- 선행연구 [The Power of Personality](https://arxiv.org/abs/2502.20859)는 다섯 특성의 조합을 다룬다. 우리 설계는 한 특성씩 비교한다.
- 동일 모델, 공통 지시, 과제, 출력 제약, 생성·추론 예산을 유지한다. 특성과 무관한 창의성·품질 지시를 조건별로 다르게 넣지 않는다.

## 결과 평가

### 평가 축

1. **새로움:** 사전에 정한 비교 대상에 비해 아이디어가 실질적으로 새로운가? (정의는 미확정, 아래 참고)
2. **유용성:** 브랜드·과제에 적합하고 연구자가 발전시킬 가치가 있는가? 50단어 형식에 완전한 실행 계획을 요구하지 않는다.
3. **다양성:** 같은 조건의 여러 아이디어가 서로 다른 방향을 탐색하는가? 집합 수준에서 따로 측정한다(v1: bge-large 임베딩).

새로움과 유용성은 각각 1~5점이며 모든 원점수를 보존한다. 연구자 본인에게 유용한지와 전문가 집단의 일반적인 선호는 구별하며, 개인 평가를 일반화하지 않는다.

### 종합점수

> **[결정 2026-11-12]** 대표 종합점수는 산술평균 `100 × (0.5 × (새로움−1)/4 + 0.5 × (유용성−1)/4)`이다. 아이디어별로 계산한 뒤 브랜드 동일 가중으로 집계한다. 조화평균은 보조 지표로 남긴다(한 축이 1점이면 0점). 다양성은 종합점수에 합치지 않고 따로 보고한다. 결정 시점은 파일럿 v1 결과를 본 뒤이며, v1에서도 같은 공식이 사전 명시된 주 종합점수였다. 기준 구현은 `experiments/pilot_v1/report.py`다.

- 쌍대 비교 승률을 유용성과 50:50으로 합치지 않는다. 새로움 척도를 바꿀 경우의 후보(A–E)와 검증 계획은 `experiments/pilot_v1/novelty_v2/COMPOSITE_OPTIONS.md`에 있다. 어느 것도 채택하지 않았다.

## 지금까지의 결과

### 파일럿 v1 (탐색적)

- 설정: 브랜드 5개(IKEA, Klarna, Roblox, Slack, Unesco), 조건당 아이디어 30개(브랜드당 6개). 생성은 claude-sonnet-5-5, 평가는 claude-opus-4-7 한 개.
- 종합점수는 O_H 69.2가 가장 높고 A_H 58.3이 가장 낮았다. BASE는 61.7이다. BASE 대비 95% 구간이 0을 벗어난 조건은 O_H(+7.5)뿐이다. 여러 대비를 동시에 봤으므로 우연일 수 있다.
- 개방성은 High가 새로움에서, Low가 유용성에서 앞서서 종합점수 차이가 거의 0이다. 종합점수만 보면 이 맞교환이 가려진다.
- **문제:** 새로움 점수가 4~5점에 몰렸다. 이 때문에 새로움 측정 연구(v2, v3)를 별도로 했다.
- 보고서: `experiments/pilot_v1/results/report_v1.1.md`

### 새로움 측정 v2 (2026-11-12, 기존 아이디어 재평가, Claude)

- 개선 루브릭은 몰림을 4점에서 3점으로 옮겼을 뿐 분포를 넓히지는 못했다. 재평가 κ는 0.73으로 기존 루브릭(0.58)보다 높았다.
- 쌍대 비교는 첫 번째로 제시된 아이디어 쪽으로 치우쳤다(62.7%). 사전 규칙에 따라 한 순서로만 묻는 방식은 제외했다.
- 비용 약 10.74 USD(정가 기준, 실제로는 구독 사용).

### 새로움 측정 v3 (2026-11-13, 사람 평가와 비교)

- 루브릭 수정은 Gemini(gemini-3.1-pro-preview), 최종 TEST는 GPT-4.1이 맡았다. 수정 범위는 범주 정의 한 곳(v2c)이다.
- 연구자 1명의 블라인드 평가(test: 아이디어 43개, 쌍 24개)와 비교했다.

| 방법 (GPT-4.1) | 사람 새로움과의 ρ | 95% CI |
|---|---|---|
| 개선 루브릭 v2c | 0.21 | [−0.12, 0.51] |
| 쌍대 비교 (두 순서 평균) | 0.10 | [−0.21, 0.40] |
| 기존 루브릭 | −0.25 | [−0.45, −0.04] |

- **사전 규칙상 사람 판단을 따른다는 근거가 있는 LLM 새로움 측정은 없었다.** Claude 결과도 ρ −0.02~0.09였다.
- 확인된 것: GPT-4.1에서는 개선 루브릭이 기존 루브릭보다 사람과 더 잘 맞았다(Δρ CI가 0을 넘음). 기존 루브릭은 110개 중 100개에 5점을 줬다. 개선 루브릭은 "선례 없음" 단정이 0건이었다.
- 쌍대 비교는 GPT-4.1에서도 앞쪽 선호가 컸다(71%). 순서를 뒤집으면 30%에서 승자가 바뀌었다.
- Claude에서 보였던 조건 간 새로움 차이는 GPT-4.1에서 재현되지 않았다(p 0.62). "조건이 새로움을 바꾼다"는 결론은 현재 평가자에 따라 달라진다.
- 사람 평가 쪽에서 본 점:
  - 연구자의 새로움과 유용성 상관이 ρ 0.67로 높다. LLM에서는 두 축이 거의 독립이었다.
  - 연구자 자신의 절대 점수와 쌍 판단이 50%만 일치했다.
  - 사람은 같은 브랜드 안에서 반복된 개념(IKEA 이혼 가구 나누기)에 낮은 점수를, Slack "서비스 스스로 끄기"에 높은 점수를 줬다. LLM은 반대였다.
  - 유용성도 사람과 LLM의 상관이 ρ 0.14–0.15로 낮다.
- 비용 약 3.71 USD(Gemini 134건, OpenAI 1,060건).
- 해석: `experiments/pilot_v1/novelty_v3/results/해석_v3.md`

## 다음 결정 (연구자)

1. **새로움의 정의**를 정한다. 측정 방법이 여기에 따라 달라진다.
   - 시장 기준 새로움: 현재 LLM 루브릭 방식
   - 이 아이디어 집합 안에서의 드묾: 반복된 개념에 감점. 임베딩 거리 같은 계산 지표가 더 투명할 수 있으나 다양성 지표와 겹치지 않게 설계해야 한다.
   - 연구자에게 새로운 관점: 개인 기준이며 일반화할 수 없다.
2. **사람 평가 보강** 여부: 평가자를 2–3명으로 늘리거나, 같은 연구자가 시간을 두고 일부를 다시 평가해 사람 자체의 일관성을 잰다. 쌍 시트는 순서를 뒤집은 판도 만든다.
3. **사람 평가 v1 시트**(`human_rating_blind_v1/rating_sheet.csv`, 66개)를 평가할지 정한다. 유용성 측정의 LLM–사람 일치는 아직 근거가 약하다.
4. 위 결정 후 **본 실험 v2**의 사전 명세에서 "확인 필요" 항목을 확정하고 실행 승인 여부를 정한다. 예상 호출 수와 비용은 실행 전에 다시 확인한다.

## 인간 평가 자료의 한계

원 논문의 전문가 평가는 익명화된 **기존 응답 쌍에 대한 선호**이며 새 결과물의 개별 새로움·유용성 정답 레이블이 아니다. 확보되더라도 LLM 평가자와 인간 선호 전반의 일치를 볼 뿐, 새 결과물의 점수를 직접 주거나 새 평가 기준을 검증하지는 않는다. 자료가 없으면 있다고 가정하지 않는다.

연구자 본인의 블라인드 평가는 새로움 시트만 마쳤고 v1 시트는 아직이다. 보정용(calibration)과 검증용(test) 행을 분리했고, 평가자가 1명이고 표본이 작으므로 결과는 탐색적이다. 사람 평가 키 파일(`..._key_DO_NOT_OPEN_until_rating_done/`)은 평가를 마친 뒤에만 연다.

참조 사례 자료(Cannes Lions The Work, WARC, Effie, AdForum 등)는 대부분 구독이 필요하거나 접근을 확인하지 못했다. 따라서 "선례 없음" 판단을 모델 기억에 맡기지 않는다.

## 동료 연구와의 관계

동료는 같은 모델·도구·행동 규칙에서 Big Five 지시가 도구 선택, 호출 인자, 재시도, 성공률, 토큰에 주는 영향을 검토한다. 이 프로젝트는 기획 아이디어 결과물에 집중한다. 모델과 성격 조건의 정의를 가능한 범위에서 맞추되, 과제가 다르면 효과 크기를 직접 비교하지 않는다. CognitionLight 관련 첨부 논문은 추론 방식·전환 제어에 관한 별도 참고이며, Big Five 성격 프롬프트의 출처가 아니다.

## 실행 환경과 원칙

- 모델 인증: v1은 Claude Code CLI 구독 인증을 쓴다. v2·v3는 프로젝트 루트 `.env`의 `OPENAI_API_KEY`, `GEMINI_API_KEY`를 읽는다. 키는 채팅·로그·데이터 파일에 쓰지 않는다.
- 호출마다 프롬프트 전문, 원시 응답, 요청 파라미터, 반환 모델, 토큰, 추정 비용을 기록한다. 비용은 기록된 토큰 × 정가로 추정하며 실제 청구서가 우선한다.
- 결과를 보기 전에 분석 계획을 고정하고 SHA-256 해시를 남긴다. 고정 뒤에 프롬프트를 고치면 새 버전으로 저장하고 새 표본으로 다시 확인한다.
- 이전 버전의 파일과 결과는 수정하지 않고 새 버전으로 저장한다.
- API 호출이 필요하면 먼저 예상 호출 수와 비용을 확인하고 허용 범위 안에서 진행한다.
- 결과를 과대 해석하지 않는다. 표본이 작은 결과는 탐색적이라고 명시한다.

| 성격 조작 확인 | Gemini로 지정했으나 방식 미확정 (아래 3번) |

역할마다 모델을 나누는 이유:

1. **자기 선호 편향을 줄인다 (생성 모델 ≠ 평가 모델).** LLM 평가자는 같은 모델이나 같은 회사 모델의 글을 더 높게 볼 수 있다. v1은 Claude가 생성하고 Claude가 평가했다.
2. **루브릭 과적합을 막는다 (DEV 모델 ≠ TEST 모델).** 루브릭을 한 모델의 출력에 맞춰 고치면, 개선이 아니라 그 모델의 버릇에 맞춘 것일 수 있다. 수정에 쓰지 않은 모델로 확인해야 개선이 일반적인지 알 수 있다.
   - 같은 회사 모델은 학습·정렬 방식이 비슷해 편향도 비슷하다. 그래서 DEV와 TEST는 회사까지 다르게 둔다.
   - v3에서는 Claude와 Gemini가 같은 범주 정의를 다르게 해석했고, 그 덕분에 루브릭의 모호한 부분이 드러났다.
3. **성격 조작 확인은 예외다.** 이 단계는 성격 지시를 받은 생성 모델이 실제로 그 성격을 표현하는지 확인한다(v1: 같은 Claude sonnet이 IPIP-50 자기 보고).
   - 다른 모델이 같은 지시로 설문에 답하면, 측정되는 것은 그 모델의 성격 표현이다. 아이디어를 쓴 생성 모델의 성격 표현은 알 수 없다.
   - 다른 모델은 관찰자로만 쓸 수 있다. 생성된 아이디어에 특성이 드러나는지 평가하는 방식이며, 자기 보고와는 다른 측정이다. 어느 방식으로 할지는 실행 전에 정한다.
4. **결론이 평가자에 따라 달라지는지 확인한다.** v3에서 Claude 평가로 보였던 조건 간 새로움 차이(p ≈ 0.02)가 GPT-4.1에서는 재현되지 않았다(p 0.62). 평가자가 하나뿐이면 조건 효과와 평가자 특성을 구분할 수 없다.

모델 분리로 해결되지 않는 것:

- **어느 모델이 사람 판단에 맞는지는 알 수 없다.** 그 기준은 사람 평가다. v3에서는 어떤 조합도 사전 기준을 넘지 못했다.
- **더 중요한 안전장치는 따로 있다.** 사람 평가 test 행을 루브릭 수정에 쓰지 않고, TEST 전에 루브릭과 분석 계획을 고정하는 것이다.
- **버전 간 비교가 어려워진다.** 모델이 바뀌면 이전 버전 점수와 그대로 비교할 수 없으므로, 바뀔 때마다 새 버전으로 저장한다.
