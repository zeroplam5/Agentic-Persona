# 블라인드 코딩 안내 (파일럿 v5, 연구자 2인)

이 폴더의 `coding_sheet_researcherA.csv`, `coding_sheet_researcherB.csv`는 내용이 같다. 두 연구자가 **서로 상의하지 않고** 각자 채운다.

- 각 행은 최종 기획안 하나다.
  - 같은 후보 묶음에서 나온 최종안이 여러 번 나온다. 서로 다른 작성 절차에서 나온 것이다.
  - 어떤 절차로 만들었는지는 가렸고, 순서는 무작위다.
- `_key_DO_NOT_OPEN_until_coding_done/`은 두 사람 모두 코딩을 마친 뒤에만 연다.
- 범위: 12개 후보 묶음(브랜드당 4) × 4개 절차 × 첫 반복 = 48건.
- 판단은 **보이는 글에서만** 한다. 표현이 비슷하다는 이유만으로 같은 요소로 보지 않는다. 요소가 **하는 일**을 비교한다.
- **요소를 더한 것 자체는 좋거나 나쁜 것이 아니다.** 아래 Q5에서 역할을 따로 판단한다.

## 문항

| 열 | 판단 | 값 |
|---|---|---|
| Q1_main_code | 최종안의 **핵심 기제**에 맞는 코드. 제목과 주된 문장으로 판단하고, 보조 설명은 보지 않는다 | 아래 코드북, 맞는 것이 없으면 Z |
| Q2_selected_core_retained | 선택 후보(`selected_candidate`)의 핵심 발상이 최종안의 **주된 발상**으로 남았는가 | yes / partial(남았지만 다른 기제가 앞서거나 흐려짐) / no |
| Q3_added_elements_from_other_candidates | 선택 후보에는 없고 **다른 후보 글에 비슷한 것이 있는** 요소. 장치, 의식, 채널, 대상, 제휴, 상품 등. 문구, 어조, 위험 관리(동의, 개인정보, 시범 범위)는 제외 | `요소=C?; 요소=C?`, 없으면 비움 |
| Q4_role | Q3의 각 요소가 최종안을 이끄는가 | main / auxiliary |
| Q5_function | Q3의 각 요소의 역할 | needed / develops / extra / unclear (아래 정의) |
| Q6_*_in_final | 반복 보조 요소가 최종안에 있는가. 해당 브랜드 열만 채운다 | 0 / 1 |

**Q5 정의**
- **needed:** 이 요소가 없으면 의뢰 주제나 선택 발상의 목적이 분명히 덜 충족된다.
- **develops:** 선택 발상의 기제를 더 구체적이거나 실행 가능하게 만든다.
- **extra:** 선택 발상에 필요 없는 별도 기능이다. 범위를 넓히거나 다른 후보의 발상을 나란히 덧붙인다.
- **unclear:** 글만으로는 판단할 수 없다.

## 사례와 경계 사례 (파일럿 v4 출력)

1. **Dior: 다른 후보의 표식이 보조로 들어온 경우**
   - 선택 후보는 아카이브 재구성(D)이다. 최종안: "Every transformed piece carries a lineage record and a small star stitched inside."
   - 별은 다른 후보(표식 후보)에서 왔다.
   - 코딩: Q1 = D, Q2 = yes, Q3 = `안감 속 별=C3`, Q4 = auxiliary, Q6 MARK = 1.
   - Q5는 판단할 문제다. 별이 재구성 발상을 구체화하면 develops, 별도의 표식 기능을 나란히 붙인 것이면 extra다.
2. **Canva: 여러 후보 요소가 한꺼번에 들어온 경우**
   - 선택 후보는 첫 유료 작업물(D)이다. 최종안에 고용주 팀 버전과 도시별 집계가 함께 있다.
   - 각각 HR 키트 후보, 도시 데이터 후보와 비슷하다.
   - 이 과제는 B2B 맥락(Canva 업무용)을 요구한다. 그래서 고용주 버전은 needed일 수도 있다.
3. **Mastercard 경계 사례: 결제음** (일반 규칙. 특정 최종안에서 가져온 예가 아니다)
   - 최종안에 특별한 결제음만 있고, 가게 표식이나 느린 계산대가 없을 수 있다.
   - 이때 MERCHANT_RECOGNITION 여부는 그 소리가 **가게 쪽에서 서두르지 않음이나 알아봐 줌을 표시하는지**로 판단한다. 두 사람이 함께 결제했음을 알리는 효과음이면 0으로 둔다.
4. **선택 후보 원문에 이미 있던 요소는 Q3에 넣지 않는다.**
   - 예: 선택 후보의 핵심 문장에 고용주 키트가 이미 있으면, 최종안에 있어도 Q3에는 넣지 않는다. Q6에는 1로 둔다.

## 결과 사용

- 두 연구자의 일치도는 Q1·Q2는 Cohen's κ, Q3은 요소 단위 일치율로 계산한다.
- 계산한 일치도를 LLM 코더 결과(`experiments/selection_focus_v5/data/codes.jsonl`)와 비교해, LLM 코더 지표를 그대로 써도 되는지 판단한다.
- 이 시트를 채우기 전까지 v5 보고서의 유입 지표는 **LLM 코더 판정**이다.
