# 블라인드 코딩 안내 v1.1 (2026-11-26 확정)

- 결정 질문 12개는 모두 권장안으로 정했다(2026-11-26). 범위를 정하지 않은 항목은 §5의 MARK_ACT 하나다.
- 이 파일과 시트의 해시는 `FREEZE_v1_1.txt`에 있다. 고치면 v1.2로 새로 고정한다.

## 1. 기본 원칙

- 각 행은 최종 기획안 하나다. 어떤 절차로 만들었는지는 가렸고, 순서는 무작위다.
- 두 연구자는 **서로 상의하지 않고** 각자 평가한다.
- `_key` 등 분석자 전용 폴더는 열지 않는다.
- 판단은 **보이는 글에서만** 한다.
  - 표현이 비슷하다는 이유만으로 같은 요소로 보지 않는다. 요소가 **하는 일**을 비교한다.
  - 글에 쓰이지 않은 전제로 연결하지 않는다.
- **요소가 더해진 것 자체는 좋거나 나쁜 것이 아니다.** 역할은 Q5에서 따로 판단한다.
- 이 코딩은 **요소가 들어왔는지와 그 역할**을 본다. 아이디어가 좋은지, 사용자가 만족하는지, 생각을 넓혀 주는지는 측정하지 않는다.
- **기준 판본:** 한국어 번역을 기준으로 평가한다. 영어 원문은 '원문' 탭에 있다.
  - 번역이 의심되면 시트 1의 '번역 확인' 칸에 표시하고 메모에 이유를 쓴다.
  - 'Claude 번역(검토 필요)'으로 표시된 최종안은 특히 영어 원문과 함께 본다.

## 2. 파일과 탭

| 탭 | 내용 |
|---|---|
| 안내 | 이 문서의 요약 |
| 원문 | 최종안마다 한 줄. 선택 후보, 후보 C1–C4, 최종안(한국어·영어) |
| 시트1_최종안 | 최종안마다 한 줄. Q1, Q2, 다른 후보 요소 있음/없음, Q6, 메모 |
| 시트2_요소 | 다른 후보 요소마다 한 줄. 최종안마다 빈 줄 4개가 있다. 모자라면 아래에 행을 추가하고 item을 적는다 |

- 연노란 칸만 입력할 수 있다.
- 목록이 있는 칸은 목록에서만 고른다. 직접 쓰거나 붙여 넣지 않는다.

## 3. 시트1_최종안

| 칸 | 값 |
|---|---|
| Q1 핵심 코드 | 브랜드 코드 목록에서 고른다(예: `Dior-C`). **후보 번호(C1–C4)가 아니다** |
| Q2 선택 발상 유지 | yes / partial / no |
| 다른 후보 요소 | **있음 / 없음 중 하나를 꼭 고른다.** 있음이면 시트2에 적는다 |
| Q6 (해당 브랜드 칸만 열림) | 0 / 1. 다른 브랜드 칸은 잠겨 있다 |
| Dior MARK_ACT, 수선한 사람 | §5 참고 |
| Q6 근거 문장 | Q6 칸에 하나라도 1이 있으면 **반드시** 최종안 문장을 복사한다 |
| 번역 확인 | 번역이 의심되면 '의심'을 고른다 |
| 메모 | 대상 문항을 앞에 적는다. 예: `Q2: …`, `전체 유사: …`, `Q6 넓은 해석: …` |

## 4. 시트2_요소

| 칸 | 값 |
|---|---|
| 요소 이름 | **짧은 이름**(예: "팀 서명판", "안감 속 별"). 문장을 붙여 넣지 않는다 |
| 최종안 근거 문장 | 최종안에서 그 요소가 나오는 문장을 **그대로 복사**한다. 해석은 메모에 쓴다 |
| 출처 후보 | 그 행의 **선택되지 않은 후보 번호**만 목록에 있다 |
| 선택 후보에도 있었나요? | 예 / 아니오 (§6-2) |
| 출처 후보 근거 문장 | (선택) 출처 후보에서 비슷한 문장을 복사한다 |
| Q4 역할 | main / auxiliary (§6-4) |
| Q5 기능 | needed / develops / extra / unclear (§6-5) |
| 메모 | 판단이 애매하면 이유를 쓴다 |

**다른 후보 요소의 범위**
- 선택 후보에는 없고 **다른 후보 글에 비슷한 것이 있는** 요소다.
- 장치, 의식, 채널, 대상, 제휴, 상품 등을 말한다.
- 문구, 어조, 위험 관리(동의, 개인정보, 시범 범위)는 제외한다.

## 5. Q6 반복 보조 요소

**원칙**
- **0/1은 아래 정의 문구대로 정한다.** 넓은 해석은 메모에 `Q6 넓은 해석:`으로 따로 남긴다.
- **1이면 근거 문장을 반드시 적는다.**
- **Q6은 '최종안에 있는가'만 본다.** 어디서 왔는지, 역할이 무엇인지는 묻지 않는다.

| 브랜드 | 칸 | 정의 |
|---|---|---|
| Dior | MARK | 수선한 옷에 장인이나 하우스가 더하는 표식, 서명, 이니셜, 날짜, 라벨, 별, 서명 카드 |
| Dior | MARK_ACT | 옷에 표식을 남기지 않고, 사람이 공개적으로 수선하는 행위 자체가 서명 역할을 한다고 보는 경우 |
| Canva | EMPLOYER_KIT | 고용주, 관리자, HR, 팀이 신입에게 보내거나 쓰는 판, 키트, 채널 |
| Canva | KEEPSAKE | 첫 급여 순간을 액자로 걸거나 인쇄하거나 공유할 수 있는 기념물·카드. **액자, 인쇄, 공유 중 하나가 글에 쓰여 있을 때만 1.** 팀이 보내는 축하·응원 메시지만으로는 1이 아니다(그 메시지는 EMPLOYER_KIT에 해당할 수 있다) |
| Mastercard | MERCHANT_RECOGNITION | 가게 쪽의 알아봐 주기 또는 느긋한 계산대 층. 단골 표식이나 스티커, 이름 불러 주기, 결제 때 고른 이름 표시, 느린 줄, 더 느리거나 따뜻한 결제음 |
| Mastercard | PAID_INVITATION | 다른 사람에게 보내는 선불 초대나 대접. 흔히 둘이 함께 있어야 열린다 |

**MARK_ACT**
- MARK 정의는 바꾸지 않았다. MARK_ACT는 MARK와 별도로 기록한다. 두 칸이 모두 1일 수 있다.
- MARK_ACT=1이면 '수선한 사람'을 고른다: 디자이너 / 장인·아틀리에 직원 / 기타 / 글에 없음
- 어떤 사람까지 MARK_ACT로 셀지는 아직 정하지 않았다. 이 기록으로 나중에 범위를 정해 센다.

## 6. 판단 기준

### 6-1. 후보 번호와 Q1 코드는 다르다

| | 후보 번호 | Q1 코드 |
|---|---|---|
| 무엇인가 | 이 행의 후보 묶음에서 몇 번째 후보인가 | 브랜드 코드북의 핵심 기제 |
| 형식 | C1–C4 | `Dior-A`, `Canva-F2`, `MC-A1` … |
| 쓰는 곳 | 시트2 출처 후보 | 시트1 Q1 |

같은 번호라도 행마다 다른 후보다.

### 6-2. 선택 후보에 이미 있던 요소 vs 다른 후보 요소

판단 순서:
1. 최종안에서 요소를 찾는다.
2. **다른 후보에 같은 기능이 있는가?** 없으면 적지 않는다. 새로 생긴 요소는 필요하면 메모에 쓴다.
3. 있으면 시트2에 한 줄을 쓰고 출처 후보 번호를 고른다.
4. **선택 후보 원문에도 같은 기능이 있는가?** 있으면 '예', 없으면 '아니오'를 고른다.

**재해석 연결**
- 선택 후보에 이미 있던 장치를 다른 후보의 발상과 같은 기능으로 읽었다면, 시트2에 쓰고 **'예'**를 고른다.
- 분석에서는 '아니오' 줄은 **새 유입**, '예' 줄은 **재해석 연결**로 나눠 센다.

**문장이 없는 연결은 세지 않는다**
- 요소는 최종안 문장 하나 이상에 연결되어야 한다.
- 전체 느낌(예: '전체적으로 함께하게 만든다')이나 글에 없는 전제(예: '이 서비스를 쓰려면 자리가 필요하다')만으로는 시트2에 적지 않는다.
- 그런 판단은 시트1 메모에 `전체 유사:`로 쓴다.
- 한 과제의 후보들은 같은 주제를 공유한다. 주제가 같다는 것만으로는 유입이 아니다.

### 6-3. Q6과 유입은 따로 본다

| | Q6 | 시트2 |
|---|---|---|
| 묻는 것 | 지정 요소가 최종안에 있는가 | 다른 후보와 같은 기능의 요소가 있는가 |
| 출처 | 묻지 않음 | 후보 번호 |
| 역할·기능 | 묻지 않음 | Q4, Q5 |

- 예 1: 다른 후보에서 온 표식이 최종안에 있다. → Q6=1이고, 시트2에도 한 줄을 쓴다('아니오').
- 예 2: 선택 후보에 이미 있던 표식이 최종안에 있다. → Q6=1이다. 시트2에는 다른 후보와 연결해 읽은 경우에만 쓴다('예').

### 6-4. main과 auxiliary

- **main:** 그 요소를 지우면 **최종안의 핵심 기제(Q1 코드)가 바뀐다.** 또는 그 요소가 제목이나 첫 문장의 중심이다.
- **auxiliary:** 지워도 핵심 기제는 그대로다. 보조 장치, 선택지, 후속 단계('2막'), 변형판이 여기에 든다.
- main이면 보통 Q2는 partial이나 no다. Q2=yes인데 main이라면, 메모에 `Q4:`로 이유를 쓰면 허용한다.

### 6-5. needed, develops, extra, unclear

아래 순서대로 묻는다.
1. **글만으로 판단할 수 없는가?** → unclear. 다른 범주가 애매하다는 이유만으로 쓰지 않는다.
2. **이 요소가 없으면 의뢰 주제나 선택 발상의 목적이 분명히 덜 충족되는가?** → needed
   - 예: 의뢰가 업무용 맥락을 요구했는데, 그것을 채우는 요소가 이것뿐이다.
3. **선택 발상이 하는 일을 돕는 수단, 형식, 세부인가?** → develops
   - 예: '하루 행사' 발상에 행사를 알리는 방식이 붙음.
4. **선택 발상과 따로 자기 일을 하는 별도 기능인가?** → extra
   - 예: '하루 행사' 발상에 별개의 상품 라인이 나란히 붙음.

- 역할은 좋고 나쁨이 아니다. extra도 사용자에게 가치가 있을 수 있다.
- 예시는 지어낸 일반 예다.

## 8. 사례 (v4 출력과 일반 규칙)

1. **다른 후보의 표식이 보조로 들어온 경우 (Dior):**
   - 상황: 선택 후보는 아카이브 재구성이다. 최종안에 "작은 별을 안쪽에 수놓는다"가 있고, 별은 표식 후보에서 왔다.
   - 코딩: Q1 `Dior-D`, Q2 yes, 시트2에 `안감 속 별 / 표식 후보 번호 / 아니오 / auxiliary`, Q6 MARK=1.
   - Q5: 별이 재구성 발상을 구체화하면 develops, 별도의 표식 기능을 나란히 붙인 것이면 extra.
2. **여러 후보 요소가 한꺼번에 들어온 경우 (Canva):** 요소마다 시트2에 한 줄씩 쓴다. 과제가 업무용 맥락을 요구하면 고용주 버전은 needed일 수 있다.
3. **결제음 경계 사례 (Mastercard, 일반 규칙):** 소리가 가게 쪽에서 서두르지 않음이나 알아봐 줌을 표시할 때만 MERCHANT_RECOGNITION=1. 두 사람이 함께 결제했다는 효과음이면 0.
4. **재해석 연결 (일반 규칙):** 선택 후보에 있던 장치를 다른 후보의 발상으로 읽었다면, 시트2에 쓰고 '선택 후보에도 있었나요? = 예'를 고른다.

| Q1, Q2 | 최종안 | κ. Q2는 일치율과 빈도도 함께 |
| 유입 여부와 출처 | 최종안 × 선택되지 않은 후보 3개 | 이진값 κ. '새 유입'만 센 것과 '재해석 연결'까지 센 것을 따로 계산 |
| Q6 | 최종안 × 해당 브랜드 칸 | 일치율. 한쪽 값에 치우치면 PABAK도 함께 |
| Q4, Q5 | 두 사람이 같은 최종안 문장을 인용한 요소 쌍 | 쌍이 약 20개 이상일 때만 κ. 그보다 적으면 표로만 보인다 |

**판정 기준 (승인됨)**
- 사람끼리 유입 여부 κ < 0.4이면 정의부터 고친다. 실험은 늘리지 않는다.
- 사람끼리 κ ≥ 0.6이고 합의값과 LLM의 κ ≥ 0.6이면, 새 실험의 유입 지표에 LLM 코더를 쓴다.
- 24건 안팎에서는 κ의 신뢰구간이 넓다. 이 기준은 진행 여부를 정하는 근거일 뿐이다. LLM 코더의 신뢰성을 확정하지 않는다.
- 이 시트를 채우고 조정하기 전까지, v5 보고서의 유입 지표는 **LLM 코더 판정**이다.
