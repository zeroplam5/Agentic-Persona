# v1.1a 추가 사항: 본평가 6건 (2026-11-26)

`CODING_GUIDE_v1_1.md`의 평가 기준(§1–§8)은 그대로 쓴다. 바뀐 것은 표본 크기, 평가자 수, 결과 사용(§9–§10)뿐이다.

## 1. 무엇이 바뀌었나

| | v1.1 | v1.1a |
|---|---|---|
| 본평가 | 24건 | **6건** (브랜드마다 2건) |
| 평가자 | A, B 두 사람 | **A 필수, B는 선택.** B가 하지 않으면 A의 평가만 쓴다 |
| 보정 9건(B) | B가 먼저 코딩 | B가 참여해도 **하지 않는다.** B는 가이드를 읽고 6건만 평가한다 |
| 파일 | `main_researcher*_24.xlsx` | `main_researcherA_6.xlsx`, `main_researcherB_6.xlsx` |

24건 파일은 지우지 않고 고정된 채로 둔다. 쓰지 않는다.

## 2. 6건 구성

- 브랜드마다 2건이다. 같은 브랜드의 2건은 서로 다른 후보 묶음에서 나왔다.
- 네 작성 절차가 모두 한 번 이상 들어간다.
- 기존 한국어 번역이 있는 최종안만 넣었다. Claude가 번역한 2건은 뺐다.
- 보정 9건과 겹치지 않는다.
- 세트와 절차의 대응은 분석자 전용 파일에만 있다.

## 3. 결과 사용 (v1.1 §9의 κ 기준은 쓰지 않는다)

6건, 평가자 1–2명으로는 κ를 계산해도 뜻이 없다. 그래서 결과는 **사례별 대조표**로만 보고한다.

**할 수 있는 것**
- 연구자 A(와 B)의 판단을 LLM 코더 판정과 사례별로 나란히 보인다.
  - Q1, Q2: 6건
  - 다른 후보 유입: 최종안 × 선택되지 않은 후보 = 18쌍
  - Q6: 해당 브랜드 칸 10개
- 어긋나는 사례에서 이유를 본다. 정의 차이인지, LLM 코더의 놓침인지, 사람의 판단 차이인지를 가린다.
- LLM에는 '재해석 연결' 범주가 없다. 그래서 유입 비교는 연구자의 **'새 유입'(선택 후보에도 있었나요? = 아니오)**만으로 한다. 재해석 연결은 따로 센다.

**할 수 없는 것**
- 사람 평가자 간 일치도. B가 참여해도 6건으로는 계산하지 않는다.
- LLM 코더의 신뢰성 확인이나 확정
- 조건 간 효과 비교
- 브랜드나 묶음 전체로 일반화하기

**진행 판단 (사전에 정함)**
- 18쌍 중 새 유입 판단이 어긋난 쌍이 **2쌍 이하**이고, 한쪽 방향으로 치우치지 않았다고 하자(예: LLM만 계속 더 많이 셈).
  - 그러면 v5 보고서의 유입 지표는 LLM 코더 값으로 두되, "단일 연구자 6건 점검에서 큰 불일치 없음"이라는 한계를 함께 적는다.
- 3쌍 이상 어긋나거나 한쪽으로 치우쳤다면, LLM 유입 지표는 **탐색적 결과**로만 보고한다.
  - 이 경우 추가 실험의 결과 지표로 LLM 코더를 쓰지 않는다.
- Q5(needed/develops/extra/unclear)는 비교할 쌍이 적다. 사례만 서술하고, 판단 근거로 쓰지 않는다.
- 이 기준은 진행 여부를 정하는 최소 점검이다. 검증이 아니다.
