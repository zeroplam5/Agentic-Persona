# 블라인드 코딩 안내 v1.1 (초안, 2026-11-26)

> **초안이다.** 두 연구자가 검토하고 승인하기 전에는 본평가에 쓰지 않는다. 승인하면 해시로 고정한다.
> v1(`human_coding_blind_v5_focus/CODING_GUIDE.md`)에서 바뀐 곳은 ✱로 표시했다. 코드북 표와 Q6 정의표는 v1과 같다(정의 문구를 바꾸지 않았다).
> 이 안내의 예시는 일부러 일반적인 예로 만들었다. 평가할 최종안에서 가져온 예가 아니다.

## 1. 기본 원칙

- 각 행은 최종 기획안 하나다. 어떤 절차로 만들었는지는 가렸고, 순서는 무작위다.
- 두 연구자는 **서로 상의하지 않고** 각자 평가한다.
- 판단은 **보이는 글에서만** 한다. 표현이 비슷하다는 이유만으로 같은 요소로 보지 않는다. 요소가 **하는 일**을 비교한다.
- **요소가 더해진 것 자체는 좋거나 나쁜 것이 아니다.** 역할은 Q5에서 따로 판단한다.
- ✱ **이 코딩은 요소가 들어왔는지와 그 역할을 본다.** 아이디어가 좋은지, 사용자가 만족하는지, 생각을 넓혀 주는지는 측정하지 않는다.
- ✱ **기준 판본 (결정 필요):** 두 연구자는 같은 판본으로 평가한다. 권장안은 한국어 번역을 기준으로 하고 영어 원문을 옆에 두는 것이다. 번역이 의심되면 '번역 확인' 칸에 표시한다.

## 2. 시트 구성 ✱

시트는 두 개다.

**시트 1: 최종안 한 줄** (최종안마다 한 줄)

| 칸 | 값 |
|---|---|
| Q1 핵심 코드 | 브랜드 코드 목록에서 고른다(예: `Dior-C`) |
| Q2 선택 발상 유지 | yes / partial / no |
| 다른 후보 요소 | **있음 / 없음** 중 하나를 꼭 고른다. 빈칸으로 두지 않는다 |
| Q6 (해당 브랜드 칸만 열림) | 0 / 1 |
| Q6 근거 문장 | Q6=1이면 최종안 문장을 복사한다 |
| 번역 확인 | 번역이 의심되면 표시 |
| 메모 | 대상 문항을 앞에 적는다(예: `Q2: …`) |

**시트 2: 다른 후보 요소** (요소마다 한 줄. 시트 1에서 '있음'일 때만)

| 칸 | 값 |
|---|---|
| 요소 이름 | **짧은 이름**(예: "팀 서명판", "안감 속 별"). 문장을 붙여 넣지 않는다 |
| 최종안 근거 문장 | 최종안에서 그 요소가 나오는 문장을 **그대로 복사**한다. 해석은 메모에 쓴다 |
| 출처 후보 | 번호만 고른다(C1–C4). 선택 후보 번호는 목록에 없다. 자동 완성은 꺼 둔다 |
| 선택 후보에도 있었나요? | 예 / 아니오. **예이면 이 줄은 '다른 후보 요소'가 아니다.** 지우지 말고 '예'로 남긴다 |
| 출처 후보 근거 문장 | (선택) 출처 후보에서 비슷한 문장을 복사한다 |
| Q4 역할 | main / auxiliary |
| Q5 기능 | needed / develops / extra / unclear |
| 메모 | 판단이 애매하면 이유를 쓴다 |

## 3. 문항

| 문항 | 판단 |
|---|---|
| Q1 | 최종안의 **핵심 기제**에 맞는 코드. 제목과 주된 문장으로 판단하고, 보조 설명은 보지 않는다. 맞는 것이 없으면 `<브랜드>-Z` |
| Q2 | 선택 후보의 핵심 발상이 최종안의 **주된 발상**으로 남았는가. yes / partial(남았지만 다른 기제가 앞서거나 흐려짐) / no |
| 다른 후보 요소 | 선택 후보에는 없고 **다른 후보 글에 비슷한 것이 있는** 요소. 장치, 의식, 채널, 대상, 제휴, 상품 등. 문구, 어조, 위험 관리(동의, 개인정보, 시범 범위)는 제외한다 |
| Q4 | 그 요소가 최종안을 이끄는가 |
| Q5 | 그 요소의 기능 |
| Q6 | 지정한 반복 요소가 최종안에 **있는가**. 해당 브랜드 칸만 |

## 4. 헷갈리기 쉬운 구분 ✱

### 4-1. 후보 번호와 Q1 코드는 다르다

| | 후보 번호 | Q1 코드 |
|---|---|---|
| 무엇인가 | 이 행의 후보 묶음에서 몇 번째 후보인가 | 브랜드 코드북의 핵심 기제 |
| 형식 | C1, C2, C3, C4 | `Dior-A`…`Dior-H`, `Canva-A`…`Canva-K`, `MC-A1`… |
| 쓰는 곳 | 시트 2의 출처 후보 | 시트 1의 Q1 |

- 같은 번호라도 행마다 다른 후보다. 'C3'가 늘 같은 발상을 뜻하지 않는다.
- v1에서는 코드북 코드(A, B, C…)와 후보 번호(C1…C4)가 모두 알파벳이라 헷갈릴 수 있었다. v1.1에서는 코드 앞에 브랜드를 붙인다. 코드의 뜻은 바꾸지 않는다.

### 4-2. 선택 후보에 이미 있던 요소 vs 다른 후보에서 들어온 요소

판단 순서:
1. 최종안의 요소를 찾는다.
2. **선택 후보 원문에 같은 기능이 있는가?** 있으면 다른 후보 요소가 아니다. 다른 후보에 비슷한 것이 있어도 마찬가지다.
3. 없으면, **선택되지 않은 후보에 같은 기능이 있는가?** 있으면 그 후보 번호를 적는다.
4. 어느 후보에도 없으면 새로 생긴 요소다. 이 문항에서는 적지 않는다(메모는 가능).

- ✱ **결정 필요: 선택 후보의 요소를 다른 후보 발상과 같은 기능으로 다시 읽은 경우**
  - 예: 선택 후보에 있던 장치를 '이것도 일종의 서명이다'라고 보는 경우.
  - 연구자 A는 이를 다른 후보 출처로 적었다(보정 사례 답변, 2026-11-26). v1 사례 4는 선택 후보에 있던 요소를 제외했다. 두 기준이 다르다.
  - **안 1 (v1 유지):** 유입으로 세지 않는다. 해석은 메모에 남긴다. 기존 LLM 코딩, v4·v5와 그대로 비교할 수 있다.
  - **안 2 (별도 기록, 권장):** 시트 2에 적되 '선택 후보에도 있었나요? = 예'로 둔다. 분석은 '새 유입'과 '재해석 연결'로 나눠 따로 센다. 두 기준의 결과를 모두 볼 수 있다.
  - 두 연구자가 정하기 전에는 두 사람 모두 **안 2의 방식으로 기록**한다. 그러면 어느 안을 택해도 다시 코딩하지 않아도 된다.
  - 보정 9건 중 4건(사례 1, 4, 6, 9)이 이 유형이었다. 어느 안을 택하느냐에 따라 유입 수가 크게 달라진다.
- ✱ **요소는 최종안 문장 하나 이상에 연결되어야 한다 (제안)**
  - 전체 뉘앙스(예: '결제로 만남을 주선한다는 느낌')나 글에 없는 전제(예: '만남에는 자리가 필요하다')만으로는 다른 후보 요소로 세지 않는다.
  - 브랜드 과제 자체가 후보들의 공통 주제일 때 특히 그렇다. 주제가 같다는 이유만으로 유입이 늘 수 있다.
  - 이런 판단은 시트 1 메모에 `전체 유사:`로 쓴다. 따로 셀 수 있게 남겨 둔다.
  - 보정 사례 2, 5가 이 유형이었다. 연구자 승인이 필요하다.
- 선택 후보 요소가 최종안에서 조금 넓어진 것(대상 추가 등)도, 넓어진 부분이 다른 후보의 기능과 같지 않으면 유입이 아니다.

### 4-3. Q6(있는가)와 유입(어디서 왔는가)은 따로 본다

| | Q6 | 다른 후보 요소 |
|---|---|---|
| 묻는 것 | 지정 요소가 최종안에 있는가 | 선택 후보에 없던 요소가 다른 후보에서 왔는가 |
| 출처 | 묻지 않는다 | 후보 번호를 적는다 |
| 역할·기능 | 묻지 않는다 | Q4, Q5를 적는다 |

- 같은 요소가 두 곳에 다 나올 수 있다. 예: 선택 후보에 없던 표식이 다른 후보에서 왔다면, Q6=1이고 시트 2에도 한 줄을 적는다.
- 선택 후보에 이미 있던 표식이면 Q6=1이고, 시트 2에는 적지 않는다.
- **Q6의 0/1은 정의표의 문구대로 정한다.**
- ✱ **결정 필요: 공개 수선 행위를 MARK로 볼 것인가**
  - 연구자 A는 '디자이너가 공개적으로 수선하는 것은 사실상 제품에 서명이 들어간 것과 같다'고 보았다(2026-11-26).
  - 현재 정의는 '수선한 옷에 더하는 표식'이다. 사람의 수선 행위는 들어 있지 않다.
  - **권장:** MARK는 그대로 두고, Dior에 **별도 칸 `MARK_ACT`(하우스의 디자이너·장인이 공개적으로 수선하거나 서명 역할을 하는 행위)**를 둔다. 기존 수치와 비교할 수 있고, 연구자 A의 기준도 따로 셀 수 있다.
  - 범위도 정해야 한다. 디자이너만 해당하는가, 장인(프티트 맹 등)도 해당하는가.
  - 정하기 전에는 MARK 0/1을 현재 정의로 정하고, 확장 해석은 메모에 `MARK_ACT:`로 쓴다.
- ✱ **결정 필요: KEEPSAKE에 축하·응원 메시지를 넣을 것인가**
  - 보정 사례 3에서 연구자 A는 팀의 축하 메시지를 기념물로 읽었다.
  - 현재 정의는 '첫 급여 순간을 액자로 걸거나 인쇄하거나 공유할 수 있는 기념물·카드'다.
  - 팀이 신입에게 보내는 메시지는 EMPLOYER_KIT에 이미 해당한다. KEEPSAKE까지 넓히면 한 문장으로 두 칸이 함께 1이 된다.
  - **권장:** 액자, 인쇄, 공유가 글에 쓰여 있을 때만 KEEPSAKE=1로 한다.
- ✱ **Q6=1에는 근거 문장을 꼭 적는다.** 보정 사례에서 근거 문장이 없는 1이 있었다(질문 후 0으로 재검토).

### 4-4. main과 auxiliary

- **main:** 그 요소를 지우면 **최종안의 핵심 기제(Q1 코드)가 바뀐다.** 또는 그 요소가 제목이나 첫 문장의 중심이다.
- **auxiliary:** 지워도 최종안의 핵심 기제는 그대로다. 보조 장치, 선택지, 후속 단계, 확장판이다.
- **점검:** main이면 보통 Q2는 partial이나 no다. Q2=yes인데 main이라고 판단했다면 메모에 이유를 쓴다.
- 고객이 '고를 수 있는' 선택지나 '2막', '변형판'처럼 덧붙은 것은 대개 auxiliary다.

> 연구자 확인 필요: 연구자 A의 최초 코딩에서 Q2=yes와 Q4=main이 함께 나온 경우가 있었다. 위 정의가 연구자의 의도와 같은지 검토해 주세요.

### 4-5. needed, develops, extra, unclear

아래 순서대로 묻는다.

1. **글만으로 판단할 수 없는가?** → unclear. 다른 범주가 애매하다는 이유만으로 unclear를 쓰지 않는다.
2. **이 요소가 없으면 의뢰 주제나 선택 발상의 목적이 분명히 덜 충족되는가?** → needed. (예: 의뢰에 '업무용 맥락'이 요구됐는데, 그것을 채우는 요소가 이것뿐이다.)
3. **선택 발상의 기제를 더 구체적이거나 실행 가능하게 만드는가?** 같은 기제를 위한 수단, 형식, 세부다. → develops. (예: '하루 행사' 발상에 행사를 알리는 방식이 붙음.)
4. **선택 발상과 다른 별도 기능인가?** 범위를 넓히거나 다른 후보의 발상을 나란히 덧붙인다. → extra. (예: '하루 행사' 발상에 별개의 상품 라인이 나란히 붙음.)

- develops와 extra를 가르는 질문: **이 요소가 선택 발상이 하는 일을 돕는가, 아니면 자기 일을 따로 하는가?**
- 역할 판단은 좋고 나쁨이 아니다. extra도 사용자에게 가치가 있을 수 있다.

## 5. 반복 보조 요소 (Q6) 정의 — v1과 같음

| 브랜드 | 칸 | 정의 |
|---|---|---|
| Dior | MARK | 수선한 옷에 장인이나 하우스가 더하는 표식, 서명, 이니셜, 날짜, 라벨, 별, 서명 카드 |
| Canva | EMPLOYER_KIT | 고용주, 관리자, HR, 팀이 신입에게 보내거나 쓰는 판, 키트, 채널 |
| Canva | KEEPSAKE | 첫 급여 순간을 액자로 걸거나 인쇄하거나 공유할 수 있는 기념물·카드 |
| Mastercard | MERCHANT_RECOGNITION | 가게 쪽의 알아봐 주기 또는 느긋한 계산대 층. 단골 표식이나 스티커, 이름 불러 주기, 결제 때 고른 이름 표시, 느린 줄, 더 느리거나 따뜻한 결제음 |
| Mastercard | PAID_INVITATION | 다른 사람에게 보내는 선불 초대나 대접. 흔히 둘이 함께 있어야 열린다 |

✱ 다른 브랜드 칸은 잠근다(N/A). 브랜드를 넘는 영향은 이 문항에서 묻지 않는다. 그런 판단은 메모에 쓴다.

## 6. 코드북

v1과 같다. 코드 앞에 브랜드를 붙인다(`Dior-A`, `Canva-F2`, `MC-A1`). 코드의 뜻은 v1 표를 그대로 쓴다.

## 7. 사례 (v1 사례 1–4 유지, 문구만 정리)

1. **다른 후보의 표식이 보조로 들어온 경우 (Dior, v4 출력):** 선택 후보는 아카이브 재구성. 최종안에 "작은 별을 안쪽에 수놓는다"가 있고 별은 표식 후보에서 왔다. → Q1 `Dior-D`, Q2 yes, 시트 2에 `안감 속 별 / C? / 아니오 / auxiliary`, Q6 MARK=1. Q5는 별이 재구성 발상을 구체화하면 develops, 별도의 표식 기능을 나란히 붙인 것이면 extra.
2. **여러 후보 요소가 한꺼번에 들어온 경우 (Canva, v4 출력):** 요소마다 시트 2에 한 줄씩 쓴다. 과제가 업무용 맥락을 요구하면 고용주 버전은 needed일 수 있다.
3. **결제음 경계 사례 (Mastercard, 일반 규칙):** 소리가 가게 쪽에서 서두르지 않음이나 알아봐 줌을 표시할 때만 MERCHANT_RECOGNITION=1. 두 사람이 함께 결제했다는 효과음이면 0.
4. ✱ **선택 후보에 있던 요소를 다른 후보의 시각으로 다시 읽은 경우:** §4-2의 결정 전에는 시트 2에 적고 '선택 후보에도 있었나요? = 예'로 둔다. 어떻게 셀지는 두 연구자가 정한다.
