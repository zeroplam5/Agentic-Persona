## 0. 사용자 결정 사항 (2026-11-12)

| 항목 | 결정 |
|---|---|
| 나머지 특성 | 표적 특성 외 4개 특성을 **Average로 명시** |
| 대조 조건 | 추가 |
| 대표 종합점수 | `100 × (0.5 × (새로움−1)/4 + 0.5 × (유용성−1)/4)`, 아이디어별로 계산한 뒤 집계. 조화평균은 보조 지표 |

## 1. 조건 (13개)

| ID | 시스템 프롬프트 앞에 붙는 문장 | 역할 |
|---|---|---|
| BASE | 없음 | 성격 미지정(원 벤치마크 그대로) |
| ALL_AVG | `Your Big Five personality profile is: Openness to Experience: Average; Conscientiousness: Average; Extraversion: Average; Agreeableness: Average; Neuroticism: Average.` | 성격 조건의 **1차 비교 기준**. 표적 특성만 다르고 나머지는 같다 |
| CTRL | `Your work profile is: Office: Head office; Department: Brand strategy; Schedule: Standard hours; Workspace: Shared desk; Language: English.` | 위약(placebo). 같은 형식과 비슷한 길이지만 성격 내용이 없다 |
| O_H … N_L (10개) | 위 템플릿에서 표적 특성만 High 또는 Low, 나머지 4개는 Average | 성격 조건 |

- 템플릿 출처: Low/Average/High 범주형 표현은 Boone et al.(arXiv:2611.06572)의 CAT 형식을 따랐다. 원 논문은 `{profile}`의 실제 문자열을 공개하지 않았으므로 **이 문구는 우리가 정한 것**이다. v1의 CEUR 문구(`You have High X.`)와는 다르다.
- 위치: 원 Creativity Benchmark 시스템 프롬프트 앞, 빈 줄 하나(v1과 같음).
- 조건별 최종 프롬프트 전문은 `logs/condition_prompts.json`에 남긴다.

### 대조 조건으로 분리하려는 효과

| 비교 | 답하려는 질문 |
|---|---|
| 성격 조건 − ALL_AVG | 표적 특성의 높음·낮음 효과(형식과 나머지 특성은 동일) |
| High − Low | 같은 특성의 양 극단 차이 |
| CTRL − BASE | 프로필 형식의 문장을 추가하는 것만으로 생기는 효과(v1에서 다양성이 거의 모든 조건에서 오른 현상 점검) |
| ALL_AVG − CTRL | 형식이 같을 때 '성격 내용'이 만드는 차이 |
| ALL_AVG − BASE | "보통"을 명시하는 것과 성격을 지정하지 않는 것의 차이 |

> **확인 필요:** ALL_AVG는 사용자의 "Average 명시" 결정에서 자연스럽게 따라 나오는 기준이라 제안자가 추가했다. 사용자가 요청한 대조 조건은 CTRL(위약)로 이해했다. 둘 중 하나만 원하면 `pilot2.py`의 `REFERENCE_CONDITIONS`에서 뺄 수 있다.

## 2. 모델과 설정 — v1의 사고 모드 교란 해결

v1(Claude Code CLI)에서는 성격 문장에 따라 내부 사고 사용 비율이 0~100%로 달라졌고, 이를 통제할 수 없었다. v2는 API에서 설정을 명시한다.

| 역할 | 제안 모델 | 설정 | 근거 |
|---|---|---|---|
| 생성 | `gpt-4.1-2025-04-14` (OpenAI, 날짜 고정 스냅샷) | temperature 1.0(원 논문과 같음), max_tokens 300, 추론 모델 아님 | 스모크 테스트에서 `reasoning_tokens: 0` 확인. 숨은 사고가 없어 조건 간 추론 예산이 같다 |
| 평가 | `gemini-3.1-pro-preview` (Google) | temperature 0.0, thinking budget 1,024 고정 | 생성 모델과 다른 회사(자기 선호 편향 완화). 평가자는 조건을 보지 않고, 모든 아이디어에 같은 설정을 쓴다 |

- 제외한 후보(2026-11-12 스모크 테스트): `gemini-2.5-flash`와 `gemini-2.5-pro`는 이 계정에서 404(신규 사용자 제공 중단). `gemini-3.8-flash`는 `thinkingBudget=0`을 줘도 사고 토큰 284개를 써서 출력이 잘렸다. 사고를 끌 수 없으므로 생성 모델로 부적합하다.
- 평가 모델이 preview 버전이라 서빙 버전이 바뀔 수 있다. 호출마다 `modelVersion`을 기록한다.

> **확인 필요:** 생성·평가 모델 선택. v1(Claude Sonnet)과 생성 모델이 다르므로 v1과 v2 결과를 직접 비교하지 않는다. Claude를 계속 생성 모델로 쓰려면 Anthropic API 키가 필요하다(CLI로는 사고 사용을 통제할 수 없다).

## 3. 표본

- 브랜드: Appendix A.2의 12개 범주에서 시드(20261113)로 범주 10개를 뽑고, 범주마다 브랜드 1개를 뽑는다. 반복은 브랜드×조건마다 6회다.
- 규모: 13조건 × 10브랜드 × 6 = 생성 780회, 평가 780회 + 재검사 156회, 조작 확인 39회.
- 비용: 가격표를 추정하지 않았다. `config.json`의 `price_per_million_tokens_usd`에 현재 가격을 넣으면 토큰 기록으로 계산할 수 있다.

> **확인 필요:** 브랜드 수(10)와 반복 수(6). 브랜드 5개와 조건당 30개였던 v1은 부트스트랩 구간이 매우 넓었다.

## 4. 평가와 지표 (확정)

- 새로움·유용성 채점표는 v1과 같다(`prompts/judge_prompt.txt`). 평가자는 브랜드와 아이디어 문장만 본다.
- **대표 종합점수:** 아이디어별 `100 × (0.5 × N + 0.5 × U)`, 여기서 N = (새로움−1)/4, U = (유용성−1)/4.
- **집계:** 브랜드별 평균을 먼저 구하고, 브랜드 평균을 같은 비중으로 평균한다. 결측 때문에 셀 크기가 달라져도 브랜드 비중이 같게 유지된다.
- **비교:** 브랜드 안의 차이를 브랜드에 걸쳐 평균하고, 브랜드 단위 부트스트랩으로 95% 구간을 구한다(10,000회).
- **표시:** 순위와 차이는 원자료로 계산하고, 표시할 때만 반올림한다(소수 9자리 정리 후 사사오입). 원자료가 같으면(오차 1e-9 이내) 같은 순위를 준다.
- **보조 지표:** 조화평균 `100 × 2NU/(N+U)`(어느 한 축이 1점이면 0점), 바닥 비율, 점수 분포와 쏠림.
- **다양성:** 브랜드×조건 6개 집합의 bge-large-en-v1.5 평균 쌍별 코사인 거리. 종합점수에 합치지 않는다.
- **조작 확인:** IPIP-50 자기보고, 조건당 3회. 표적 특성의 변화와 표적 외 특성의 변화를 ALL_AVG 기준으로 본다.

### 알려진 위험: 새로움 천장

v1에서는 새로움 점수의 96.7%가 4–5점이었다. 채점표를 바꾸면 v1과 비교할 수 없게 되므로 이번 초안에서는 **바꾸지 않았다**.

> **확인 필요:** 새로움 앵커를 조정할지, 또는 쌍대 비교를 보조로 추가할지.

## 6. 해석 원칙 (v1과 같음)

탐색적 파일럿이며 p값을 쓰지 않는다. 확인된 성격별 순위로 해석하지 않는다. 사람 평가와의 일치를 검증하기 전에는 LLM 점수를 "품질"로 단정하지 않는다. 조작 확인은 자기보고 설문이다.
