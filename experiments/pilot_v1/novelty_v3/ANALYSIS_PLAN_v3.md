# 새로움 측정 v3 — 분석 계획 (OpenAI TEST 실행 전 작성·고정)

작성일: 2026-11-13. 이 문서의 SHA-256 해시는 `logs/freeze.json`에 기록한다. 함께 기록하는 파일은 프롬프트, 설정, 표본, 사람 평가 파일이다. 사람 평가 test 행과의 일치도는 동결 뒤에만 계산한다.

## 바뀐 점 (v2 대비)

- **역할을 나눈 평가 모델:** 루브릭 수정 과정에서 평가 모델 판정을 보는 데는 Gemini(`gemini-3.1-pro-preview`)를 쓴다. 최종 TEST 채점은 OpenAI(`gpt-4.1-2025-04-14`)가 맡는다. 두 모델 모두 temperature 1.0이다. 이렇게 하면 수정에 쓴 모델과 최종 확인 모델이 서로 다르다.
- **같은 표본과 설계:** 아이디어, DEV/TEST 분할, 쌍 설계는 v2와 같다(`../novelty_v2/logs/sample.json`).
- **사람 평가:** 연구자 1명이 조건과 LLM 점수를 모르는 상태에서 평가했다.
  - 절대 새로움: 55개 (calibration 12, test 43)
  - 쌍대 비교: 30쌍 (calibration 6, test 24)
  - 유용성: 연구자가 직접 추가한 열이다.
- **사람 calibration 행의 용도:** 루브릭 점검에만 썼다. 그 아이디어 12개도 LLM TEST 110개에 들어 있다. 따라서 사람 일치도는 test 행에서만 보고하고, calibration 행은 따로 표시한다.

## DEV 기록 (Gemini)

1. **v2b 그대로 적용 (DEV 55 + 사람 calibration 12)**
   - 점수 분포: 2점 6 · 3점 38 · 4점 11.
   - 규칙 위반: `precedent_recall = close`(같은 작동 방식)인데 3점을 준 경우가 35건이었다. 루브릭상 close는 최대 2점이다. Claude에서는 이 칸이 거의 전부 "loose"였다.
   - 두 모델 모두에서 이 칸의 정의가 모호하다는 것이 확인됐다.
   - 사람 calibration 12개와의 Spearman은 −0.27이었다.
   - 불일치는 두 갈래였다.
     - IKEA "이혼 시 가구 나누기" 아이디어: 같은 브랜드 안에서 반복된 개념이다. 사람은 2점, LLM은 3–4점을 줬다.
     - Slack "서비스 스스로 끄기" 아이디어: 사람은 4–5점, LLM은 2–3점이었다. LLM은 이를 익숙한 "브랜드가 스스로를 끄는" 형식으로 봤다.
   - 이 두 갈래는 루브릭 결함이 아니라 판단 관점의 차이로 보았다. 12개, 평가자 1명에 맞춰 루브릭을 바꾸면 과적합이므로 반영하지 않았다.
2. **유일한 수정 v2c**
   - 바꾼 것은 `precedent_recall` 하나다. 이 칸을 `relation_to_closest`로 바꾸고, 네 범주와 각 범주에 허용되는 점수 범위를 명시했다.
     - same_mechanism → 1–2점
     - modified_familiar → 3점 (익숙한 형식 두 개를 나란히 붙인 경우 포함)
     - loose_analogue_only → 4점
     - none_recalled → 5점, 또는 4점
   - 점수 기준과 다른 문장은 그대로 두었다.
   - Gemini DEV 결과: 2점 2 · 3점 48 · 4점 5. 범주와 점수가 모두 일관됐다.
   - 사람 calibration 12개의 점수는 v2b와 완전히 같았고 이름표만 바뀌었다.
   - Claude v2b와의 Spearman은 0.26에서 0.48로 올랐다.
3. **TEST에 쓰는 프롬프트:** `novelty_abs_v2c`, `novelty_pair_v1`(수정 없음), 기존 v1 루브릭.

## OpenAI TEST 호출 (TEST 아이디어 110개, 쌍 275개)

- **절대평가:**
  - 개선 v2c: 2회 (220건)
  - 기존 루브릭: 2회 (220건). 새로움과 유용성을 함께 받는다.
- **쌍대 비교:**
  - 275쌍 모두 원래 순서(AB)와 뒤집은 순서(BA)로 평가한다 (550건).
  - 그중 70쌍은 같은 순서로 한 번 더 평가한다.
  - v2에서 한 순서만 묻는 방식이 제외됐기 때문에, 이번에는 두 순서의 평균을 쓴다.
- **호출 순서:**
  - 1차: 절대평가 1회차, 쌍대 AB.
  - 2차: 절대평가 2회차, 쌍대 BA, 쌍대 반복.

## 사람 기준 지표 (test 행만)

- **(a) 주 지표:** 사람 절대 새로움 43개와의 Spearman ρ. 아이디어 부트스트랩 5,000회로 95% 구간을 구한다.
- **(b) 보조 지표:** 사람 쌍대 24쌍과의 일치율.
  - 3범주(A/B/SIMILAR) 완전 일치율과, 사람과 방법 모두 승부를 낸 쌍에서의 방향 일치율을 본다.
  - 절대평가 방식은 두 아이디어의 점수 차이 부호로 쌍 판정을 예측한다. 점수가 같으면 SIMILAR로 본다.
- **보고만 하는 지표:** 단일 회차의 완전 일치율, 가중 κ, 평균 이동.
- **유용성:** 사람 대 Claude v1, 사람 대 GPT-4.1. 결정에는 쓰지 않는다.

## 결정 규칙

1. **최소 기준:** (a)의 95% 구간 하한이 0보다 큰 방법이 M1–M3 중 하나도 없으면, "LLM 새로움 점수가 이 평가자의 판단을 따른다는 근거 없음"으로 결론 낸다. 이 경우 본 실험에서 LLM 새로움을 주 결과로 쓰기 전에 사람 평가를 늘리거나(평가자 추가) 측정을 재설계하도록 권고한다.
2. **방법 선택:** 최소 기준을 넘는 방법 가운데 (a)가 가장 높은 것을 후보로 둔다.
   - 그 후보와 M2의 ρ 차이에 대한 짝 부트스트랩 95% 구간이 0을 포함하면, 더 단순하고 근거 문장이 남는 M2를 쓴다.
3. **(b)는 방향 확인용이다.** (a)와 결론이 다르면 그대로 보고한다. 결정은 (a)를 따른다.
4. **확정 범위:** 평가자가 1명이고 표본이 작으므로, 위 결정은 다음 파일럿에서 쓸 측정의 "잠정" 선택이다. 결과에 따라 프롬프트를 다시 고치지 않는다. 고친다면 그것은 새 버전(v4)이며, 새 사람 평가 표본으로 다시 확인해야 한다.
