## 1. 연구 질문

선택한 후보의 핵심 목적과 필요한 실행 요소에 집중하도록 점검하면, 기존 방식이나 원장 방식과 비교해 최종안의 발상 유지, 요소 유입, 과제 적합성이 어떻게 달라지는가?

다른 후보 요소의 유입 자체를 실패로 보지 않는다. 결합은 선택한 발상을 발전시키거나 과제에 필요할 수 있다. 그래서 유입의 **수**와 **역할**을 따로 본다.

## 2. 자극과 정보 노출 (조건 간 동일)

- **세트:** v4의 24세트(3브랜드 × 8)를 그대로 쓴다. 후보 원문은 v3 생성 결과이고, 순서는 v4에서 섞은 그대로다.
- **선택 기록:** v4 `data/select.jsonl`의 공통 선택 기록을 모든 조건에 그대로 준다. 이번에는 선택을 다시 호출하지 않는다.
- **모든 조건의 수정 단계 입력에 공통으로 들어가는 것:**
  - 후보 4개 전체 원문: id, title, core_idea, brand_connection, expected_strengths, main_concerns
  - 선택 기록 전체: 선택 이유, 그리고 다른 후보마다 선택하지 않은 이유
- **따라서 이번 비교에서 달라지는 것은 지시뿐이다.** 다른 후보 원문은 모든 조건에서 계속 보인다. "다른 후보를 보여주지 않는 것"의 효과는 이번 설계로 알 수 없다(§9 후속 제안).
- **선택 기록에 이미 들어 있는 흡수 계획:** 24개 선택 기록 중 5개는 선택 이유에 "absorb"(다른 후보의 요소를 흡수하겠다는 계획)가 명시돼 있다.
  - 해당 세트: Dior SB_O_H|2, Dior SB_O_L|0, Dior SB_AVG|3, Canva BASE|2, Canva SB_O_L|3
  - 이 5세트는 하위 집단으로 따로 보고한다.

## 3. 조건

| 조건 | 수정 단계 지시 | 프롬프트 |
|---|---|---|
| BASELINE | 수정 기록 → 최종안 (v3·v4와 같은 문구) | `prompts/revise_BASELINE_user.txt` = v4 `revise_baseline_user.txt`와 바이트 동일 |
| LEDGER | 다른 후보·새 요소를 하나씩 나열하고 출처·목적·포함 여부·이유를 기록 → 수정 → 최종안 | `prompts/revise_LEDGER_user.txt` = v4 `revise_intervention_user.txt`(v4 REVIEW)와 바이트 동일 |
| FOCUS | 선택안의 핵심 목적, 핵심 방향, 필요한 요소, 발전 계획을 기록 → 다른 후보 요소를 가져온 경우에만 무엇을 왜 가져왔는지 기록 → 수정 → 최종안 | `prompts/revise_FOCUS_user.txt` |
| NEUTRAL | 요소를 검토하지 않는 같은 분량의 작업 기록 → 수정 → 최종안 | `prompts/revise_NEUTRAL_user.txt` |

- **FOCUS:** 다른 후보 요소를 금지하지 않는다("Combining is allowed when it serves the core purpose"). 다른 후보 요소 전체를 나열하라고 요구하지도 않는다("You do not need to list or review the other candidates' elements").
- **NEUTRAL:** 독자, 독자가 알아야 할 것, 용어, 어조, 구성, 명료성 점검을 적게 한다. 추가 요소에 대해서는 아무 지시도 하지 않는다.
- **NEUTRAL을 포함한 이유:**
  - v4에서는 원장 내용과 출력량 증가가 섞여 있었다.
  - 스모크에서 출력 토큰은 BASELINE 904, LEDGER 2,239, FOCUS 2,513, NEUTRAL 2,239였다. 분량 통제가 가능하다.
  - 추가 비용은 약 $2–3(명목)이다.
- **모든 조건에 공통으로 고정한 것:**
  - 모델: claude-sonnet-5-5 (Claude CLI 2.1.141)
  - effort high, MAX_THINKING_TOKENS 8000, 출력 상한 16000, 호출당 상한 $0.6
  - 시스템 프롬프트 BASE(성격 지시 없음)
  - 최종안 형식: 150단어 이하, 질문 3개

## 4. 반복과 분석 단위

- 세트 × 조건마다 3회 호출한다. 입력은 바이트 단위로 같고, temperature는 지정할 수 없다(CLI 기본값). 총 24 × 4 × 3 = 288회다.
- 호출 순서는 시드(20261125)로 섞어 시간 효과가 조건과 겹치지 않게 한다.
- **분석 단위는 세트(24)다.** 같은 세트의 반복 3회는 독립 과제로 세지 않는다.
  - 지표마다 세트 × 조건의 반복 평균을 먼저 계산하고, 그 세트 평균을 조건끼리 짝지어 비교한다.
  - 같은 세트·조건 안의 반복 간 변동(세트 내 표준편차)도 함께 보고한다.
- **통계:**
  - 짝 차이의 평균
  - 세트 재표집 부트스트랩 95% 구간(10,000회, 시드 고정)
  - 세트 평균 차이의 부호 검정
- 다중 비교 보정은 하지 않는다. 모든 비교는 탐색적이다.
- 브랜드별 결과를 먼저 제시하고 합산은 그다음에 둔다.

## 5. 평가 (조건 가림)

1. **선택 발상 유지:** 코더가 `selected_core_retained`(yes / partial / no)를 판정한다. 최종안 핵심 코드가 선택 후보 코드와 같은지도 본다.
2. **다른 후보 요소의 유입:** 코더가 `added_elements`를 뽑는다. `similar_in`이 none이 아니면 다른 후보 요소로 센다. 역할은 main 또는 auxiliary다.
3. **유입의 역할:** 코더가 `function`을 판정한다. needed는 과제나 선택 발상의 목적에 필요한 것, develops는 선택 발상의 기제를 구체화하는 것, extra는 선택 발상에 필요 없는 별도 기능, unclear는 판단 불가다. 사전에 정의한 반복 보조 요소 5종(Dior 표식, Canva 고용주 키트·기념물, Mastercard 계산대 층·선불 초대)은 선택 후보에 없는데 최종안에 들어왔는지 본다.
4. **최종안 반복:**
   - 브랜드·조건·반복별로 8세트 최종안 핵심 코드의 HHI를 계산한다.
   - 같은 브랜드 최종안끼리의 평균 TF‑IDF 코사인 유사도도 계산한다(단어 수준, 반복별로 계산 후 평균).
   - 선택을 공유하므로 핵심 코드 분포는 조건 간 차이가 작을 것으로 예상한다.
5. **과제 적합성:** v3 판정 기준으로 브랜드 적합 B, 실행 가능성 F, 논리 L을 1–5로 매긴다(gpt-6-astra, 사람 보정 전).
6. **비용:** 조건별 호출 수, 재시도, 입력·출력 토큰, 시간, CLI 명목 비용을 기록한다.

**코더와 판정자**
- 둘 다 gpt-6-astra(reasoning low)이고, 조건 이름을 보지 않는다. 코더 입력은 후보 4개(title, core_idea), 선택 id, 최종안뿐이다. 작업 기록 절(원장, 점검, 메모)은 코더에게 주지 않는다.
- 코더 프롬프트는 v4에 `function` 항목과 "Adding elements is not in itself good or bad" 한 문장을 더했다.
- **코더 검증:** 같은 코더로 v3 원래 최종안 24개를 코딩해 분석자 수작업 핵심 코드와 비교한다. 정확 일치가 70% 이상이면 코더 결과를 주 지표로 쓴다. 70% 미만이면 보조 지표로 내리고 그 사실을 보고한다.

## 6. 가설 (방향 사전 지정)

- **H1 (주):** FOCUS의 최종안당 다른 후보 요소 수는 LEDGER보다 적다.
- **H2:** FOCUS와 BASELINE의 차이는 방향을 예측하지 않고 보고만 한다.
- **H3 (출력량 분리):**
  - NEUTRAL이 BASELINE과 비슷하고 LEDGER가 NEUTRAL보다 많으면, v4의 증가는 출력량보다 다른 후보 요소를 나열한 내용과 관련된다고 해석한다.
  - NEUTRAL도 BASELINE보다 많으면, 추가 작업 단계나 분량 자체도 관련된다고 해석한다.
- **H4 (유지):** 각 조건의 선택 발상 유지(yes 비율)는 BASELINE − 0.10 이상이다.
- **H5 (적합성 비열등):** B/F/L 세트 평균 차이의 부트스트랩 구간 하한이 −0.3 이상이다.
- **탐색:**
  - function 분포
  - 반복 보조 요소 유입
  - 최종안 반복도
  - 세트 내 반복 안정성
  - 흡수 계획 5세트 하위 집단
  - 브랜드별 차이

## 9. 해석 원칙

- 원장, 점검, 메모, 수정 기록은 모델이 **보고한** 작업 기록이다. 내부 추론이나 원인의 증거로 쓰지 않는다.
- 다른 후보 요소가 적거나 최종안이 서로 더 다르다고 해서 더 좋다고 결론 내리지 않는다.
- 범주 수 차이만으로 수렴을 말하지 않는다. 후보는 실행당 4개이고 선택은 1개이기 때문이다.
