## 2. 사전에 고정한 조건과 가설

**공통 조건**
- 세트: v4의 24세트(브랜드당 8). 후보 원문, 제시 순서, 공통 선택 기록을 그대로 쓴다.
- 반복: 세트 × 조건마다 **3회**.
- 모델: claude-sonnet-5-5(Claude CLI 2.1.141), effort high, thinking 상한 8000, 출력 상한 16000.
- 성격 지시: 없음(BASE).

| 조건 | 선택 후 지시 |
|---|---|
| BASELINE | 수정 기록 → 최종안 (v4와 바이트 동일) |
| LEDGER | 추가 고려 요소를 하나씩 나열(출처, 목적, 포함 여부, 이유) → 수정 → 최종안 (v4 REVIEW와 바이트 동일) |
| FOCUS | 핵심 목적, 핵심 방향, 필요한 요소, 발전 계획 → 다른 후보 요소를 가져왔을 때만 무엇을 왜 가져왔는지 → 수정 → 최종안. 금지하지 않고, 나열도 요구하지 않음 |
| NEUTRAL | 같은 분량의 글쓰기 메모(독자, 용어, 어조, 구성, 명료성) → 수정 → 최종안. 추가 요소에 대한 지시 없음 |

**가설**
- **H1:** FOCUS의 다른 후보 요소 수는 LEDGER보다 적다.
- **H2:** FOCUS와 BASELINE의 차이는 방향을 예측하지 않는다.
- **H3:** NEUTRAL로 출력량 효과를 분리한다.
- **H4:** 선택 발상 유지는 BASELINE − 0.10 이상이다.
- **H5:** B/F/L 차이의 95% 구간 하한은 −0.3 이상이다.

**분석 단위**
- 분석 단위는 세트 24개다. 각 세트에서 조건마다 반복 3회를 평균한 뒤, 같은 세트 안에서 조건끼리 짝지어 비교한다.
- 각 비교에서 보고하는 값:
  - 짝 차이의 평균
  - 세트 재표집 부트스트랩 95% 구간
  - 세트 수 기준 부호 검정(높음 : 낮음)
- 다중 비교 보정은 하지 않았다.

## 6. 가능한 해석과 한계

**가능한 해석 (검증 전)**
1. **"다른 후보 요소를 다시 보여준 것" 때문은 아니다.** 네 조건 모두 후보 원문을 똑같이 봤다. NEUTRAL은 원문을 보면서 분량이 늘었는데도 증가하지 않았다.
2. **원장의 '전부 나열' 요구가 원인의 전부도 아닌 것 같다.** 나열을 요구하지 않은 FOCUS도 비슷하게 늘었다.
3. **두 조건의 공통점:** LEDGER와 FOCUS 모두 "선택안에 무엇이 필요한가 / 무엇을 더할까"를 따로 적는 칸이 있다. 이 칸이 추가 요소를 생각하게 만들었을 수 있다. FOCUS의 `required_elements`와 `borrowed_elements` 칸이 그 예다. 다만 이번 설계로는 칸의 존재와 지시 문구를 가를 수 없다.
4. **늘어난 유입의 성격:** 코더 기준으로 늘어난 것은 대부분 **extra**(선택 발상에 필요 없는 별도 기능)였다. develops는 조건 간 거의 같았다. 주된 발상이 바뀐 경우는 0이었다. 정리하면 "핵심은 유지하고 보조 요소를 더 얹는" 변화다.
5. **LLM 판정에서는 그 변화가 나쁘게 평가되지 않았다.** B/F/L이 낮아지지 않았다. 사람에게 어떤지는 모른다.

**한계**
- **역할 판정:** 코더가 'needed'를 288개 최종안 전체에서 한 번도 쓰지 않았다. 코더의 needed 기준이 지나치게 엄격하거나 문구가 잘 작동하지 않은 것으로 보인다. 그래서 '과제에 필요한 결합'과 '불필요한 추가'의 구분은 **이번 자료로 판단할 수 없다.** 사람 2인 코딩이 필요하다.
- **판정자 구성:** 코더와 판정자가 같은 모델(gpt-6-astra) 하나다. 코더 검증은 분석자 1인 코드와의 핵심 코드 일치뿐이고, 요소 단위 검증은 없다.
- **표본 규모:** 24세트 × 3반복이다. 세트 내 반복 간 표준편차(약 0.35)가 효과 크기(0.4–0.7)와 비슷해서 반복이 필요했다. FOCUS−LEDGER 같은 작은 차이(−0.14)를 가르기에는 표본이 부족하다.
- **일반화 범위:** 주제는 Claude가 정한 임시값이고, 브랜드 3개, 성격 조건은 BASE 하나, 모델은 하나다.
- **설계상 고정된 지표:** 선택을 공유했으므로 최종안 핵심 발상의 집중도는 이 설계로 바뀔 수 없다. 반복의 큰 부분은 v4에서 본 것처럼 생성·선택 단계에서 정해진다.
- **작업 기록의 지위:** 원장, 점검, 메모는 모델이 **보고한** 작업 기록이다. 내부 추론이나 원인의 증거가 아니다.
