# 파일럿 v4 설계: 선택 후 요소 검토 개입 (탐색적)

작성 2026-11-23, 호출 전 고정. 해시: `logs/freeze_hashes.txt`

## 0. 선행 작업과 이 연구의 위치

- **선행 작업:** `../pilot_v3_structured/results/dior_convergence_analysis.md` (Dior 단계별 수렴 분석, §4.5 "메인/디테일" 표 포함). 이 파일럿은 그 관찰을 반복하지 않는다. 관찰된 지점(선택 후 수정 단계에서 다른 후보의 요소가 보조 장치로 들어오는 현상)에 **개입을 적용하고 비교**한다.
- **기존 자료 탐색 결과:** `results/existing_analysis.md` (Dior 외 Canva·Mastercard 포함, 같은 코딩 기준).

## 1. 질문

> 선택 후 수정 단계에 "선택안의 핵심 발상과 추가하려는 요소를 구분하고, 각 요소의 필요성을 검토하는 절차"를 넣으면, 기존 수정 절차보다 최종안의 반복(브랜드 안에서 같은 실행 요소가 되풀이되는 정도)을 줄이면서 선택한 발상, 브랜드·과제 적합성, 개연성을 유지하는가?

## 2. 왜 이 지점인가 (기존 자료 근거, 인과 주장 아님)

| 브랜드 | 반복되는 보조 요소 | 최종안이 그 요소를 핵심으로 갖지 않은 실행 중 요소가 들어간 비율 | 처음 기록된 지점 |
|---|---|---|---|
| Dior | 장인 서명·표식 | 9/9 | 선택 후보 2 · 선택 기록의 흡수 계획 → 수정 6 · 출처 없는 수정 1 |
| Canva | 고용주·HR 키트 | 24/28 | 선택 후보 12 · 선택 기록 → 수정 2 · 수정에서 추가 10 |
| Canva | 기념물(액자·공유 카드) | 12/23 | 선택 후보 3 · 선택 기록 → 수정 6 · 수정에서 추가 3 |
| Mastercard | 매장 쪽 알아봐 주기 층 | 최종안 4/18 (수정 기록에만 3) | 선택 기록 → 수정 4 |

- 요소 유입은 선택 단계의 "흡수 계획"과 수정 단계에서 함께 일어난다. Canva 고용주 키트는 생성 단계(후보 원문)에서 이미 많이 들어와 있어, 선택 후 개입만으로는 줄어들 여지가 작다고 **예상**한다.
- 선택 집중은 브랜드마다 다르다. Mastercard 선불 초대(B)는 위치와 무관하게 선택됐고, Canva는 첫 자리 효과로 대부분 설명된다(`results/existing_analysis.md` §3). 선택 단계 개입은 이번 파일럿의 비교 대상이 아니다(§8 확장 후보).

## 3. 설계

| 항목 | 내용 |
|---|---|
| 자극 | v3 구조화 기록의 **후보 4개 원문**(제목·핵심 발상·브랜드 연결·장점·우려)을 그대로 재사용. 새 후보 생성 없음 |
| 후보 세트 | 브랜드당 8세트 = v3 BASE 4세트 전부 + 나머지 24세트 중 시드 무작위 4세트. 3브랜드 24세트 |
| 제시 순서 | 세트마다 시드로 섞고 C1–C4로 다시 번호를 매김. 두 조건이 같은 순서를 받음. 원래 위치는 `logs/plan.json`에 기록 |
| 단계 1 (공통) | 선택 호출 1회: 후보 → 선택·제외 이유. **두 조건이 같은 선택 기록을 공유**한다 |
| 단계 2 (조건별) | **BASELINE:** v3 지시문 4·5번(수정 + 최종안)과 같은 문구. **REVIEW:** `element_review`(선택안 핵심 한 문장, 추가 검토 요소마다 출처·목적·포함 여부·이유) → 수정 → 최종안 |
| 고정 | 모델 claude-sonnet-5-5, CLI 2.1.141, effort high, thinking 상한 8000, 출력 상한 16000, 호출당 $0.6 상한, 시스템 프롬프트(BASE, 성격 문단 없음), 후보 수 4, 최종안 150단어 이하 + 질문 3개 |
| 호출 수 | 선택 24 + 수정 48 = Claude 72회. 코딩 72 + 판정 216 = gpt-6-astra 288회 (v3 원래 최종안 24개를 참조용으로 함께 코딩·판정) |
| 조건 수 | 성격 조건 1개(BASE)로 고정. Big Five 교차는 첫 결과를 본 뒤 확장 후보 |

**개입 문구 원칙:** 다른 후보 요소를 금지하지 않는다. "결합은 허용되고 가치가 있을 수 있다. 선택 방향이나 의뢰에 필요하면 포함하고, 아니면 뺀다. 포함한 요소는 핵심을 대체하지 않고 지원해야 한다"만 요구한다. "흔한 방향" 같은 정보는 주지 않는다(그건 다른 개입이다).

**이 설계로 분리되는 것:** 후보 생성의 우연(같은 후보 사용), 선택의 우연(같은 선택 기록 사용). 남는 차이는 단계 2 지시문과 호출 간 표본 변동이다. 반복이 1회라 표본 변동과 개입 효과를 이번 파일럿에서 분리할 수는 없다(§7).

**주의:** BASELINE은 v3 단일 호출 워크시트와 같지 않다(단계가 호출로 나뉨). v3 원래 최종안은 참조로만 보고한다.

## 4. 지표 (합치지 않고 각각 보고)

| # | 지표 | 측정 | 비교 방식 |
|---|---|---|---|
| 1 | 선택 발상 유지 | 코더: `selected_core_retained` yes/partial/no; 코더의 `final_main_code` vs 선택 후보 코드 | 조건별 yes 비율. 개입이 1세트 이상 더 낮으면 "유지 저하 신호" |
| 2 | 최종안 반복 | (a) 브랜드별 반복 보조 요소가 "선택 후보에 없는데 최종안에 있음" 비율 (b) 최종안 핵심 코드 분포(HHI, 최다 비중) (c) 최종안이 선택 후보에 없던 요소 수 | 세트 단위 짝 비교(같은 세트의 두 조건). 부호 수 보고 |
| 3 | 다른 후보 요소 활용 | 코더: `added_elements`(출처 후보, main/auxiliary). REVIEW는 자기 보고 원장(`candidate_elements`)도 별도 보고 | 조건별 평균·분포. 자기 보고와 코더 판정 일치 여부 |
| 4 | 적합성·개연성 | gpt-6-astra B/F/L (v3 루브릭, 사람 보정 전) | 조건별 평균, 세트 짝 차이. 비열등 기준: REVIEW − BASELINE 평균 ≥ −0.3 (B, F, L 각각) |
| 5 | 사람에게 주는 가치 | 조건을 가린 시트(S1–S3) | **이번에 측정하지 않음.** 시트만 준비 |
| 6 | 비용 | Claude: output_tokens, total_cost_usd(명목), elapsed_s. OpenAI: usage, 추정 비용 | 조건별 합·평균 |

- **반복 감소의 주 지표는 2(a)다.** 기존 자료에서 수렴이 주로 보조 요소 층에서 관찰됐기 때문이다. 선택이 공유되므로 2(b)는 크게 달라지지 않을 것으로 예상한다.
- 다르다는 것만으로 더 낫다고 판단하지 않는다. 2가 줄어도 1·4가 나빠지면 개입이 유리하다고 쓰지 않는다.

## 5. 코더 검증

- 코더(gpt-6-astra)는 최종안·후보·선택 ID만 본다. 조건, 수정 기록, `element_review`는 보지 않는다.
- v3 원래 최종안 24개를 같은 코더로 코딩해, 분석자(Claude) 수작업 코드(`coding_existing.py`)와 `final_main_code` 일치율을 보고한다. 일치율이 낮으면(< 70%) 코더 결과를 주 지표에 쓰지 않고 기술 자료로만 둔다.
- 사람 2인 코딩은 이번에 하지 않는다.

## 6. 분석

- 세트 24개, 조건 2개. 검정은 하지 않거나 부호 검정(정확 이항)만 기술용으로 제시한다. 브랜드별로 나눠 보고한다.
- 사례: 두 조건의 차이가 가장 큰 세트를 원문 근거와 함께 제시한다.

## 7. 한계 (미리 적음)

- 조건당 세트 1회. 같은 입력의 재실행 변동을 측정하지 않으므로 차이가 개입 효과인지 표본 변동인지 구분할 수 없다. 확장 시 세트당 반복 ≥ 3.
- 개입 조건은 출력 필드가 하나 더 많다. 토큰·시간 차이는 측정해 보고한다.
- 임시 주제(Claude가 정한 값), 3브랜드, LLM 코더·판정. 사람 평가 없음.
- 모델이 적은 `element_review`는 보고된 작업 기록이며, 실제 내부 과정의 증거가 아니다.
